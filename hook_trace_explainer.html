How ofi_hook_trace works — and how to plug in your own tracer

A bottom-up tour of the hook provider infrastructure: what runs, when, and exactly where to add your own code.

1 · The provider stack

libfabric is built around layered providers. When you open a fabric, libfabric inserts any enabled hook providers between your application and the underlying transport. Each hook wraps every operation function pointer, calls the real function, then does its own work (logging, timing, profiling).

Your application fi_send / fi_recv / fi_cq_read …
↕ hook replaces every fi_ops_* vtable
ofi_hook_trace hook provider
↕ calls through to real provider
tcp / cxi / shm / … transport provider
↕
kernel / NIC firmware hardware

Hook providers are transparent: they hold a pointer to the underlying fabric/domain/endpoint (hfabric, hdomain, hep …) and forward every call. They never change semantics.

2 · Activating hook_trace

Three environment variables are all you need:

VariableValue used in our examplePurpose
FI_HOOK trace Semicolon-separated list of hook names. libfabric calls ofi_get_hook() which prepends ofi_hook_ to resolve the provider.
FI_LOG_LEVEL trace Must be ≥ trace; otherwise FI_TRACE() macros are compiled-out no-ops at runtime.
FI_LOG_PROV (unset) Optional filter on provider name. Unset = show all. Set to e.g. tcp to see only hook_trace lines. 
# run the example with full trace
LD_LIBRARY_PATH=/path/to/install/lib:$LD_LIBRARY_PATH \
FI_PROVIDER=tcp FI_HOOK=trace FI_LOG_LEVEL=trace \
./pingpong

Under the hood, src/fabric.c:ofi_hook_init() reads FI_HOOK, splits it on ;, and stores the provider pointers in a module-global hooks[] array. Each time fi_fabric() is called, ofi_hook_install() walks that array and wraps the new fabric object.

Each line follows the format:

Flag bits decoded: 0x802 = FI_SEND|FI_MSG, 0x402 = FI_RECV|FI_MSG. The hook sees every operation in order because it sits on all vtables simultaneously.

The key structs from ofi_hook.h:

struct hook_prov_ctx {
  struct fi_provider prov;
  /* per-object init callbacks */
  hook_ini_fn ini_fid[FI_CLASS_CNTR+1];
};

struct hook_fabric {
  struct fid_fabric  fabric; /* exposed */
  struct fid_fabric *hfabric;/* real    */
  struct fi_provider *hprov; /* for logs */
  ...
};

Registration (hook_trace.c bottom)

/* Every hook provider ends with a constructor macro */
struct hook_prov_ctx hook_trace_ctx = {
    .prov = {
        .name    = "ofi_hook_trace",
        .fabric  = hook_trace_fabric,  /* called when fi_fabric() wraps */
        ...
    },
};

HOOK_TRACE_INI  /* expands to __attribute__((constructor)) function */
{
    /* install per-object initialisers */
    hook_trace_ctx.ini_fid[FI_CLASS_DOMAIN] = trace_domain_init;
    hook_trace_ctx.ini_fid[FI_CLASS_PEP]    = trace_pep_init;
    return &hook_trace_ctx.prov;
}

Wrapping an object (trace_domain_init)

static int trace_domain_init(struct fid *fid)
{
    struct fid_domain *domain =
        container_of(fid, struct fid_domain, fid);

    /* replace the vtable pointers with our wrappers */
    domain->ops = &trace_domain_ops;   /* av_open, cq_open, endpoint … */
    domain->mr  = &trace_mr_ops;       /* mr_reg, mr_regv … */
    return 0;
}

A typical wrapper (trace_send)

static ssize_t
trace_send(struct fid_ep *ep, const void *buf, size_t len,
           void *desc, fi_addr_t dest_addr, void *context)
{
    struct hook_ep *myep =
        container_of(ep, struct hook_ep, ep);

    /* 1. call through to the real provider */
    ssize_t ret = fi_send(myep->hep, buf, len,
                           desc, dest_addr, context);

    /* 2. log on success (ret == 0) */
    TRACE_EP_MSG(ret, myep, buf, len, dest_addr, 0, 0, context);

    return ret;
}
Pattern

Every wrapper: call real function → inspect result → emit trace. The hook never blocks or modifies data. The macro TRACE_EP_MSG expands to FI_TRACE(prov, FI_LOG_EP_DATA, …), which is a no-op unless FI_LOG_LEVEL ≥ trace.

5 · Writing your own hook provider

The hook infrastructure is designed for exactly this. You write a self-contained .c file that follows the same pattern as hook_trace.c. You do not need to modify libfabric's source.

Step-by-step

  1. Create the provider context and name it. 
    /* my_hook.c */
struct hook_prov_ctx my_hook_ctx = {
    .prov = {
        .version    = OFI_VERSION_DEF_PROV,
        .fi_version = OFI_VERSION_LATEST,
        .name       = "ofi_hook_myhook", /* FI_HOOK=myhook */
        .fabric     = my_hook_fabric,
    },
};
  2. Implement my_hook_fabric — called once per fi_fabric(). 
    static int
my_hook_fabric(struct fi_fabric_attr *attr,
               struct fid_fabric **fabric, void *context)
{
    struct fi_provider *hprov = context; /* real provider */
    struct hook_fabric *fab   = calloc(1, sizeof *fab);

    hook_fabric_init(fab, HOOK_TRACE, attr->fabric,
                     hprov, &my_fid_ops, &my_hook_ctx);
    *fabric = &fab->fabric;
    return 0;
}
  3. Register per-class init callbacks in the INI function. 
    MY_HOOK_INI   /* expands to __attribute__((constructor)) */
{
    my_hook_ctx.ini_fid[FI_CLASS_DOMAIN] = my_domain_init;
    /* also: FI_CLASS_EP, FI_CLASS_CQ, FI_CLASS_PEP … */
    return &my_hook_ctx.prov;
}
  4. Swap vtables in my_domain_init. 
    static int my_domain_init(struct fid *fid)
{
    struct fid_domain *d =
        container_of(fid, struct fid_domain, fid);
    d->ops = &my_domain_ops;   /* your fi_ops_domain */
    d->mr  = &my_mr_ops;
    return 0;
}
  5. Write your operation wrappers. 
    static ssize_t
my_send(struct fid_ep *ep, const void *buf,
        size_t len, void *desc,
        fi_addr_t dest, void *ctx)
{
    struct hook_ep *myep =
        container_of(ep, struct hook_ep, ep);

    /* your pre-send code: timestamp, LTTng tracepoint … */
    uint64_t t0 = my_clock();

    ssize_t ret = fi_send(myep->hep, buf, len,
                           desc, dest, ctx);

    /* your post-send code: record latency, emit event … */
    my_record("fi_send", t0, len, ret);

    return ret;
}
  6. Build as a shared library and tell libfabric where to find it. 
    gcc -shared -fPIC -o libmyhook_fi.so my_hook.c \
    -I$(LIBFABRIC_SRC)/include \
    -I$(LIBFABRIC_SRC)/src \
    $(pkg-config --cflags libfabric)

# point libfabric at the directory containing your .so
export FI_PROVIDER_PATH=/path/to/my_hook_dir
export FI_HOOK=myhook
export FI_LOG_LEVEL=trace   # if you use FI_TRACE() internally
Tip — multiple hooks

FI_HOOK accepts a semicolon-separated list: FI_HOOK=trace;myhook. The hooks stack left-to-right, innermost first. Your hook sees calls already filtered through hook_trace, and vice versa.

Headers you need

Your .c must include internal libfabric headers not installed by default: ofi_hook.h, ofi.h, and optionally ofi_prov.h. Point -I at the source tree's src/ and include/ dirs, or copy the handful of structs you actually use.
